# 已有项目升级与差异合并

仅在首次对齐或获取更新后升级项目时读取。日常工作依项目内协议执行；安装包替换见 [Agent 接入](agent-setup.md)。本页提供比较方法，项目本地规则仍由 Policy、Lifecycle、Layout 维护。

## 取得同一份来源

使用执行时选定的已提交修订，记录来源分支、不可变提交和清单指纹。源仓有未提交内容时，从 Git 读取或导出该提交；Skill、引用、模板和工具来自同一修订，不混用工作树文件。没有来源基线时明确未知，不从 Schema 或模板格式号猜具体发行。

新版 Skill 包与项目是两份独立内容。替换已安装包不会更新项目；本次项目升级也不默认授权修改全局安装、客户端配置或其他项目。

## 建立本地比较基底

读取目标 AGENTS、根和模块 README、三份按需规则、实际工具及 Git 状态，识别用户暂存、未暂存、未跟踪内容与项目定制。原项目路径、运行命令、权限、验收、预算、历史分母及私有边界均是需要保护的事实。

升级记录与既有任务分开。已有工作项正文、字段、附件和原件默认只读，规则更新用于后续；派生视图可刷新且人工区保留。有针对旧记录的明确更正指令时按其范围处理，不因模板更新批量迁移历史。

## 按职责合并

| 已有内容 | 比较与处置 |
|---|---|
| 未定制的旧工具或模板 | 核对旧/新源后采用新实现，保留必要兼容入口 |
| 项目定制协议、工具排除项、验收合同 | 明确改动目的，逐段/函数合并，保留项目特有边界及实际读取链 |
| 项目事实、架构、用法与模块职责 | 根据现行实现修订受影响说明，不用通用模板覆盖 |
| 既有工作项、冻结证据和授权原件 | 保留原路径、身份与结论；新规则不反向重写 |
| 新版取消默认生成的页或工具 | 已有内容先核对用途和来链；新骨架省略不等于授权删除旧事实 |
| 无旧源、冲突或未知内容 | 保留原文，列出具体未合并点，继续独立的升级部分 |

旧源可得时比较旧源/新源/项目现状；以文件内容与实际调用关系识别定制，清单哈希只作字节身份。合并路径、目的、处置和结果写入当前升级记录的现有章节，不另造第二台账。无法恢复的损失或超范围操作才确认，已授权可逆合并直接完成。

## 形成一套实际生效的内容

核对本地 AGENTS、根/模块入口、Workspace/WORK/现存导航、Policy/Lifecycle/Layout、五份库存、正常/回退创建与相关工具。规则详情单点维护；生成工作项只保留任务内容及短规则入口，不能把旧模板的长协议重新复制回来。

机械字段用本地 `maintain --update` 序列化，原件用 `--attach` 按真实批次保存，链接用 `--link` 从目标实际章节生成。辅助命令只减少写入错误，不判断业务结论。工具升级要包含 record_tools 依赖；不能只换入口脚本后留下旧模块。

修复实际 import、CLI、生成/读取路径、测试支持与收集、构建及文档引用。原生产品文档沿原布局；新默认不要求 project/docs 或 framework，并不授权改写已有架构事实。

## 依据实际范围收口

读取前后差异，核对用户暂存边界、原件身份、实际受影响行为与项目要求的验证。测试发现变化核对收集范围；启动或运行链变化时实际检查就绪，缺条件则记录未验证。明确不运行的检查保留未运行，不拿结构通过或旧分数替代。

在项目 AGENTS 的治理来源一处记录修订/指纹、采纳范围、保留定制和未合并差异；详细依据引用本次升级记录。部分合并不标全量采用，旧结果不记作本轮重跑。源仓同步、Skill 包加载和项目升级分别表述各自完成边界。
