# 文档内容政策

本文件规定内容归属与同步；格式和状态见 [Lifecycle](DOCUMENT_LIFECYCLE.md)，执行纪律见根 [AGENTS](../../AGENTS.md)。日常任务不必反复读取本页。

## 唯一事实源

| 信息 | 权威正文 |
|---|---|
| 项目定位、已验证能力、使用和运维 | 根 README 与 `project/docs/` |
| 当前状态、Stage、下一步、交接 | 工作项 README；状态字段只写 YAML |
| 当前有效范围、AC、授权约束及来源 | 小项 README 范围/验收章节；复杂项 Spec |
| 当前实施顺序、返修问题、技术准入条件及证据入口 | 小项 README 计划章节；复杂项 Plan |
| 重要决定、授权变化及原因 | 小项 README 必要背景；复杂项 Log |
| 实际验证、适用版本、各批次结果与限制 | 小项 README 验证章节；复杂项 Evidence |
| 已验证技术结构 | `framework/current/`；以实现与实际证据核对 |
| 已接受未来差异与长期选择 | Target、Roadmap、ADR，按需建立 |
| 入口、登记和派生视图 | 本目录 README、WORK、HISTORY、工作项管理入口 |

同一粒度事实只写一处。索引保留短结论和链接，不复制正文；工具检查只证明结构符合约定，不证明业务已经通过。

## 现行约定与历史依据

默认回流现有正文。新授权或范围变化更新当前范围、约束和 AC，并引用授权依据；后续实施安排和准入条件更新当前计划，实际技术结果留在验证记录。更新对应的现行段落，不在 README、Spec 或 Plan 末尾不断追加“最新授权”“当前技术门”等并存入口。README 保留当前状态和必要交接，详细历史从 Log 与 Evidence 进入；小项仍使用同一 README 的对应章节，不因此拆文件。

现行技术准入条件、最近执行结果和业务验收结论各有职责，通过链接关联。记录证据对应的源码、输入和实际覆盖；旧证明不能自动适用于新实现，失败、unknown、未运行及其完整分母保持原结论。Log 保存重要变更原因，Evidence 按批次保存实际依据，现行正文引用其中适用记录。

额外文件须有独立保存、引用或复核价值。授权原话已有稳定消息引用或正式审计记录时直接引用；确需离线交接、原件留存或哈希核验时才另存。授权原文与已冻结报告保持内容和来源，现行边界回流正文；修改说明本身不构成新增授权。独立专题维护一份现行正文，完整评审和执行报告按批次保留，阶段修复清单默认回流计划，不另设实施入口。路径、命名和保存约定见 [文件组织](DOCUMENT_LIFECYCLE.md#文件组织与命名)。

## 表达与同步

稳定说明先解释用途、当前能力与限制，再给必要技术细节和证据入口。工作项保存过程，产品文档保存稳定用法；未来设计不能写成已实现。

普通实施不逐命令同步。到可交接点、暂停或完成时，按实际变化判断：用户能力/运维改变同步对应产品页面；技术事实改变同步对应 Current；范围改变修订 AC；状态改变重生成视图。没有相关变化的页面不修改。

Schema 4 只记录实际受影响页面及原因，无影响写“无”，不逐项填写十类“不更新”。工具可提示路径与链接问题，不能自动判断业务文档影响。Schema 3 旧 Plan 的十类矩阵继续按原合同读取。

## 导航、图与历史

新增或移动稳定正文时，在 [导航登记表](README.md)登记职责与事实入口，修复直接链接。图只在能解释关系时添加，保留可独立理解的文字；不为每页强制建图。

已完成/取消记录、历史证据和 ADR 默认冻结。错链或明显错误可做记录日期与原因的最小更正；新的范围或结论建立新项。删除前确认内容无保留价值或已迁移、引用已修复、登记已更新。

有跨仓责任时明确外部入口、责任和合同版本，各仓维护自己的正文。单仓任务不承担无关仓库的定期仪式。稳定文档不含本机绝对路径、私人数据和未经验证的通过声明。
