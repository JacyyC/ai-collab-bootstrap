# AGENTS.md

本文件是人类与 AI 的唯一工作协议。客户端专用入口可引用本文件，不复制第二份协议。[文档政策](workspace/docs/DOCUMENTATION_POLICY.md)规定内容归属，[生命周期](workspace/docs/DOCUMENT_LIFECYCLE.md)规定记录格式；只有修改相关规则或遇到边界问题时才读取细则。

## 接手

1. 读本文件、[WORK](workspace/docs/WORK.md)和选定工作项的 README；重新查询 Git 状态，识别用户既有改动。
2. 首次进入项目或项目定位发生变化时读根 [README](README.md)；范围、实施、架构、历史按当前问题读取对应正文，不全量读取导航登记表和旧日志。
3. 阅读、解释和状态查询不建立工作项。实施时使用已有相关工作项；没有合适记录时建立最小工作项。

## 工作与记录

- 用户确认的范围和验收条件先明确；实现与验证不能为了提前结束而缩减范围。
- 小任务在工作项 README 写目标、边界、AC、必要决定和验证；多阶段或复杂任务按需拆 Spec、Plan、Log、Evidence。
- 状态、Stage、下一步只维护 README YAML；正文补充原因、风险与交接背景。详细规则见 [Lifecycle](workspace/docs/DOCUMENT_LIFECYCLE.md)。
- 普通实施不逐命令写文档；可交接检查点、暂停或完成时更新当前记录，稳定能力或架构改变时同步实际受影响正文。
- 完成前对照 AC 与实际结果。没运行的检查写未运行，工具结构检查不能替代业务验收。
- 检查点执行一次 `python3 workspace/scripts/maintain.py --checkpoint <ID>`；审查用 `--check`，不写文件。失败时修复或如实记录阻塞，不宣称完成。

## 边界与安全

- 已有项目沿用根 README 明确的代码布局，不为采用模板强制移动。`project/` 保存业务代码、测试、配置和稳定产品文档；`workspace/` 保存工作记录、治理工具、架构与未来设计。Current 只写已验证事实，Target 只写已接受目标。
- WORK、HISTORY 和工作项管理入口由工具生成，不手工修改受控区块。同一事实只维护一处；新增或移动稳定说明时登记权威位置和直接入口。
- 不回退用户或协作者改动；密钥、私人数据、数据库、缓存不进入仓库。根 `开发日志.md` 仅供人工，未经针对该文件的明确指令不得改动。
- 既有 Schema 2/3 与历史记录保持可读，新项使用 Schema 4；已完成/取消记录默认冻结，纠错写日期、原因与依据。
- 工具不自动提交、重置、部署或把工作项标为完成。产品范围、持续付费、第三方权限、生产部署、公开发布及不可逆操作按用户授权处理。

## Git

Stage 是实施与验证检查点，完成不以提交为前提；交接必须如实记录未提交状态。大规模移动前确认有可回退提交。未获明确授权不提交、不推送、不变基、不强推。

获授权后只暂存本任务文件，检查完整 diff、验收证据和统一门禁。提交首行用 `[已登记ID[/工作项已定义Stage]] 简洁中文动宾短语`；多项用 `[ID1+ID2]`，一次性非工作项维护用 `[misc]` 并说明目的。阶段起点 `head` 不回填为包含自身记录的提交哈希。
